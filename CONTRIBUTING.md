# Contributing to Skales

Thanks for your interest. Skales is proprietary software and its source is not
published, so the useful shapes of a contribution are not the usual ones. These
are the ones that reach the product.

## What helps most

1. **Bug reports.** Open an issue with your OS, Skales version, provider and
   model, and the steps to reproduce. A report against a released build is
   worth more than any patch against a tree nobody ships.

2. **Translations.** Skales speaks twelve languages, and a sentence that reads
   wrong in yours is something only you can see. Open an issue with the screen,
   the text as it stands and the text as it should read; corrections go into the
   next release with credit.

3. **Agent Skills and plugins.** Both are built on published formats and are
   yours entirely: share a skill through the Discover feed or as a `SKILL.md`,
   and a plugin exports as one file. Nothing about them needs our tree. The
   DevKit is separate, MIT-licensed and maintained at
   [skalesapp/skales-devkit](https://github.com/skalesapp/skales-devkit).

4. **Documentation.** The install guides and the docs in this repository take
   pull requests like any document.

5. **Security findings.** They have their own route and their own promises -
   read [SECURITY.md](./SECURITY.md) before you start.

## What cannot be accepted here

Code changes to Skales itself. The application is not open source and its tree
is not in this repository, so there is nothing here to patch. An idea that
belongs in the product is welcome as an issue, and a good one arrives in a
release with the reporter named in the changelog.
