# **Changelog**

All notable changes to Skales will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),

and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## v12.9.31 - Reflex

**A release that lets Skales decide small things in a fraction of a second, and gives everything it makes a way to be flagged.**

Reflex is named after the second kind of thinking the app can now do. Every question Skales answers has so far gone to the same place, the model you chose, whether it was a whole essay or a yes-or-no. A decision model answers only the small closed questions - which of these, yes or no, how much - and it answers them in a fraction of a second because it never writes a word. Switched on under Assist, it takes the next step while browsing and decides which tool steps a long conversation can spare, and the model you chose keeps doing what it does. It is off until you switch it on, it never sees a picture, and nothing about the conversation changes when it is off.

The release also carries the one small window that now sits behind everything the app produces. Report used to live under a chat answer and nowhere else, which left the screens where generated work actually stands - a preview, a gallery card, a rendered Flow piece, a diagram, a 3D model, a widget, a plugin page - with nothing to press. All of them have it now, it is the same window everywhere, and what it sends follows what is on screen rather than promising an answer text that a picture does not have. The phone and the computer write the same words for it, so one complaint is one row on our side whichever of the two it came from.

The other half of the release is the plugin floor: three plugins that do a job the app could not do before, a page that may record and keep pictures without ever being handed the microphone or the disk, a shelf that says whether a plugin can actually be used, and files that survive an update. Around both, the honesty work continues - a machine with no key stops claiming it can read or draw a picture, a helper that comes back empty names its reason, and an approval raised at the desk reaches the phone in your pocket.

### Added

- **Skales can hand its small decisions to a decision model.** Some of what Skales does between your messages is not writing at all, it is deciding: which of a handful of steps fits, whether something is worth keeping, whether a step is one you would not want taken without being asked. Those questions can now go to Jev, TypeSafe's decision model, which answers them with a plain yes-or-no or a pick from a short list, together with how sure it is - in a fraction of a second, and far more cheaply than asking a writing model to say the same thing in a sentence. It writes no text, sees no pictures and uses no tools. It is off unless you switch it on, and you can either give Skales a TypeSafe key or let it use the OpenRouter key you already have. If it is off, unreachable, slow, or answers something Skales did not ask for, Skales simply decides the way it always has - so nothing you rely on depends on it. An incognito conversation is never sent, and neither is anything while Privacy Mode is on. What it costs is counted into the same running total as the rest of the conversation. The switch sits under Chat & Code, Assist, as a second slot called Decisions, next to the model that does the small work.

- **Browsing can take its next steps in a fraction of a second.** When a decision model is switched on, Skales can work towards a goal on a page it already has open - open the article and then the section, open the second story's comments, find the cheapest of these - taking each step in a fraction of a second instead of thinking a full sentence about it first. It stops and hands the page back whenever it is unsure, whenever it is going in circles, and as soon as the goal is reached, so the ordinary careful path picks up exactly where it left off. It stops and asks before anything that buys, pays, sends, publishes, deletes or signs in, and it still asks everything your Browser Control settings say to ask about - it can only ever be more careful than the single steps, never less. It never invents text: a field is filled with the exact words from your request or not at all. Pages with nothing readable on them work the way they always did, and so does every installation with no decision model switched on.

- **Anything Skales generated can be reported, wherever it is shown.** Report used to live under a chat answer and nowhere else, which left the screens where generated work actually stands - a live HTML preview, the Studio gallery, a rendered Flow piece, a diagram, a 3D model, a widget - with no way to flag anything at all. Every one of them has it now, and it is the same small window with the same sentence above the field, not a second kind of popup per surface: right-click a preview or a gallery card, or press the flag that sits in the toolbar. The HTML preview also opens full screen now, and there the Report button stands next to the close button rather than hiding in a menu. What is sent follows what is on screen: a written answer sends its text, while a picture, a film, a piece of music, a model, a diagram or a widget has no text to send, so what travels is the sort of thing it is and the instruction it was made from - the only readable thing there is. The window names what it is looking at, too: over a picture, a film, a model, a diagram or a widget it says Report content rather than Report answer, and the line under the field names what really travels instead of promising an answer text that does not exist. The phone and the computer write the same words for all of it, so one complaint about one picture is one row on our side no matter which of the two it came from. It reaches the coding window too: a page the model printed and previewed there carries the same right-click, the same flag in its bar and a full page view with Report beside Close - and so does a plugin page and a generated 3D scene. And a reported picture now travels with what it was actually made from and the machine that drew it, rather than with the name of the file it was saved under.

- **Three plugins that do a job the app could not do before.** *Meeting Notes* records the room and writes the transcript down while the meeting is still running: the recording is cut into stretches of twenty seconds, each one is read as soon as it finishes, and each paragraph carries the minute it was spoken at - so closing the window costs the stretch that was running and nothing before it. The whole meeting hands on as Markdown. Where the sound comes from is a choice on the page, and system audio is shown there and disabled, because Skales captures the screen without its sound and a missing option reads as a hidden one. *Document Capture* files a photo, a scan or a PDF into its own folder before anything reads it, then shows what was read BESIDE the original in a box you can correct - and a text you correct is yours, so reading the document again records a second reading beside it and never over it. A captured receipt hands on into the Receipt Inbox plugin's own month sheet, keyed the way that plugin keys its rows, behind a card you answer. *Moodboard* is whole on a machine with no key at all: pictures from your disk, dragged where you want them, notes to write on and colours to put beside them, with generation offered only where this machine can actually draw.

- **A plugin page can record, and keep pictures.** Two things a page could not do before, both done by the app on the page's word rather than by the page itself. A microphone is never handed into a plugin's sandbox - Skales records and hands back the text, over the same speech wire the chat's own microphone uses - and pictures and scans are written as files in the plugin's own work folder, where an update leaves them alone and an export never carries them.

### Fixed

- **Browsing asks the decision model the question it is actually asked.** With a decision model switched on, Skales was meant to let it take the small browsing steps, and in an ordinary conversation it almost never got that far: the model doing the talking kept reaching for the single steps it already knew, so the fast path sat there switched on and unused. Two things changed. A click described in words - "the link to the article about Vienna" - now goes to the decision model first, which picks the element on the page that the description means, and only if it is not sure does the click fall back to the older text match and the picture reader, exactly as before. And the multi-step run is now named as the way to work towards a goal on a page that is already open, so it is taken rather than passed over. Everything it does still stops and asks in the same places, and an installation with no decision model browses exactly the way it did.

- **The decision model list only offers names the service answers to.** One of the two entries in the model list was spelled a way the service refuses outright, so choosing it left every decision unanswered - and because an unanswered decision quietly falls back to the ordinary way, nothing looked broken, it was just switched on and doing nothing. The list now names only spellings that work, and a setting you saved earlier keeps working without you having to touch it.

- **The line under the name on the start screen is quieter now.** It was set almost as large as the app name and pressed up against it; it is smaller now and stands a little further below the name and the gecko, so the name reads first and the line reads as what it is, a caption.

- **The menu bar icon speaks your language, and calls the Cockpit by its name.** Everything in the menu behind the Skales icon was written in English whatever language the rest of the app was set to - the status line, the provider, the count of calls this hour, the planner and goal lines, the waiting-approvals warning and every destination in the list. All of it is translated now, in all twelve languages, and the counted lines are written the way each language writes them rather than an English sentence with a number dropped into it. The menu is built fresh each time you open it, so changing the language in Settings shows up on the very next click without restarting. A machine with nothing configured yet still reads English. The entry that opens the autonomous surface is also named Cockpit now, the same name the page and the sidebar carry, instead of the older Autopilot - and so is the line that appears when the cost cap has paused it.

- **The Auto-Compact slider now governs every fold, and zero really means off.** Settings > Memory Mode has always let you say how full a conversation may get before Skales summarises its older part, and switching it off has always been a real answer for a large window. Five places fold a conversation, and exactly one of them ever asked. The other four carried a fixed three quarters: the fold at the start of a run, the one that fires when a conversation has simply grown too many entries, and the two inside the agent loop that a team run, a scheduled task, a plugin and every agent run go through. So a slider moved to forty per cent changed almost nothing, and a slider switched off still had older parts summarised away - and paid a model call to do it. All five read your number now, and at zero none of them runs: when the entry count alone forces something to give, the oldest entries are set aside instead, and the conversation says so in plain words rather than quietly shortening itself. The fold that happened silently in the middle of a long chat writes the same line as the others, so a conversation you are watching is never shortened without saying it was.

- **A system note is written the way the rest of the app writes.** The notes Skales puts into a conversation itself - the list behind /help, the tool list behind /tools, the model list, the line about a summarised conversation - are composed with bold headings, code names and one item per line, and every one of them was drawn as raw text. So the reader saw `**Quick Actions**` with its asterisks, a tool name wrapped in backticks, and in the short pill shape the line breaks collapsed into one run-on line. These notes now go through the same writing the answers use: a heading is bold, a tool name is a code chip, a list is a list, and every line break the note was written with is on screen. Nothing else about the note changes - same size, same quiet colour, same reading column, and the choice between the short pill and the card is untouched.

- **Reopening a long chat now offers its beginning back, with one press.** A conversation with hundreds of messages opens on its newest eighty so it appears at once, and a note above them says so. The note was the end of it: there was no way to see the rest, and people who wanted the start of a thread were left scrolling into a wall that would not move. The note carries a button now - it names how many older messages are waiting - and pressing it folds them in above the newest ones, in order, with pictures and tool steps drawn exactly as they are drawn everywhere else. Nothing is read from disk a second time and nothing is written: the whole conversation was already in hand, and only what you can see changes. Where you were reading stays where it was rather than the column jumping under you. Once they are all on screen the note says so, and it says nothing more. Open another conversation and come back, and it opens on its newest eighty again with the button waiting, because a look is not a setting. The three places that reopen a conversation - starting the app, picking a chat from the list, switching to another agent - now do all of this from one piece of code instead of three near-copies, and the note itself is written in all twelve languages rather than English for everybody.

- **A long system note is a card now, not a stretched pill.** Notes like the one about a summarised conversation were drawn in the same little rounded pill built for "stopped" and "queued" - and because that row had no reading width of its own, its width was measured against the whole window rather than the column the messages stand in. A paragraph therefore came out as a wide oval with half-circle ends, running past every bubble around it. The row sits in the message column now, a short note stays a pill, and anything longer is a card with normal left-aligned text.

- **A plugin page fits a phone.** Plugin pages travel to the phone whole and are drawn there in a window about a third the width of the computer's, and several of them came out wider than the screen: Document Capture put the original and the text it read side by side no matter how narrow the screen was, a table with eight columns pushed past the edge, and a picture was drawn at its own size - so the left edge of every line sat off screen until you dragged the whole page sideways. The house look every plugin page stands on now carries the narrow case itself: pictures fit the width they are given, a column pair stacks, a strip of controls wraps, and a wide table scrolls inside its own box instead of taking the page with it. Nothing changes in a computer window, and every page that ships is measured at phone width before it goes out.

- **Skales no longer claims it can read a picture on a machine with no key.** Every provider card carries its vendor's web address whether or not anybody filled it in, and an address on its own was being counted as a provider that is set up - so a machine with nothing configured was told thirteen different models could read an image for it. The pages that ask that question, and hide their setup hint when the answer is yes, therefore hid it on exactly the machine that needed it. An address counts on its own only where it is the whole configuration, which is a model running on your own computer.

- **A picture saved by Skales keeps its own name.** Everything the app serves out of the workspace comes through one route, and the name was read off that route - so every such picture downloaded as image.png, whatever it was really called.

- **Skales no longer claims it can draw a picture on a machine that cannot.** The built-in picture renderer reported itself as ready everywhere, because it needs nothing installed - but it draws by having a language model write a page and photographing it, so on a machine with no model it could not draw either. Anything that asked what this machine can make was told an image path was there; the Moodboard offered its generate card on the strength of it, and pressing the button came back with nothing tried. The answer is honest now, and it names the screen that would change it.

- **Moodboard says what is missing instead of hiding the card.** Where this machine cannot draw, the generate card is gone - and a line now stands in its place naming the setting that would bring it back. The board itself never needed any of that and still does not.

- **Document Capture files the document, then tells you what it needs.** Pressing Read it on a machine with no model ended in the reader's own error text, and the document was listed as read afterwards although nothing had read it. The page now answers that case with the same hint it shows on opening, keeps the original, leaves the entry as not read with the failed attempt recorded beside it, and Read it again works the moment a model is there.

- **A plugin page no longer opens with a red bar on a machine where nothing has happened yet.** Every bundled page asks what it has the moment it opens - its own folder, its own file, the mailbox - and on a machine where the plugin was installed a minute ago the honest answer to all three is "nothing": the folder has never been written and no account has ever been added. Both answers came back as a failure, so Receipt Inbox greeted a new reader with "There is nothing at that path" across the top, and Open Invoices said the same thing about the mailbox twice, once in red and once in the hint below it. Nothing written yet, no account and no model are now states with names of their own, the page draws each of them once in the empty state that says which screen to open, and the bar over the page is kept for what a page cannot answer. A mail server that is merely down still says so.

- **A plugin's tool call can no longer wait for ever.** Nothing ended the wait if a tool never answered - a local model that stopped replying was enough - and the page was left with a disabled button and a spinner that was still turning an hour later. A call now gives up after twenty seconds, the same as on the phone, says so, and can be tried again.

- **The plugin pages count the plugins that ship instead of naming a number.** Three places said ten ship inside the app; thirteen do. The sentence now takes the number from the list itself, in all twelve languages, so it cannot fall behind the shelf again.

- **The chat list in the sidebar no longer goes stale after deleting a conversation.** Deleting a chat left the sidebar showing the deleted one and, worse, hiding every conversation started afterwards - while the history page and the dropdown at the top were both right, which made it look like the new chats had not been saved at all. They had been; only the sidebar was reading a copy from before the delete and trusting it for the next half minute. It now reads the list again after a delete and whenever a new conversation is created, and a copy taken before a delete is never treated as current.

- **The licence names its licensor with a name and a mailbox.** The contact line of the agreement carried a city as well; it is now Mario Simic, trading as Skales, request@skales.app, in the English and the German text alike.

- **A helper that comes back with nothing now says why.** A run could pay for several helpers and end with "they delivered nothing", which is the one thing that account must never say. Each helper that returns empty-handed now names its reason - it used up its step budget, it stopped on an error, it looked and found nothing, or the model answered without writing a word - the headline counts how many came back empty, and the run passes the reason on to you instead of flattening it.

- **The grey bar under the conversation is gone.** A table wider than the column made the whole transcript scroll sideways, drawing a bar across the window under everything. A table now scrolls inside its own box, the way a code block and a diff already do, and the transcript scrolls in one direction only.

- **A narrow Code window lays itself out again instead of stacking on top of itself.** Below a laptop's width the file panel, the review card and the input field piled over each other and the two side rails kept a column's width as a height, pushing the rest off the screen. Everything in the stack now gives way in proportion, the rails become a strip with their own scroller, and a dialog opened from inside a panel covers the window rather than a third of it.

- **Opening the preview keeps the split.** The preview and the repository panel could not shrink, so with both of them open the conversation was squeezed to nothing and the layout fell into a single column. Both panels now give way down to a sensible minimum, and the ceiling on a panel you dragged wider is measured against the window's own workspace rather than the whole screen, which was systematically too generous when the coding window runs inside the app.

- **The file tree and the Changes list tell the truth about a folder.** A session bound to a folder whose ignore rules are written as a whitelist showed a handful of files and "Changes 1" over a session that had just written a folder full of them. Changes now lists what the repository itself reports, file by file rather than one line for a whole new folder, and it no longer inherits the tree's filter. The tree says out loud how much the folder's own ignore rules are keeping out of it, instead of looking like a window that cannot read the disk.

- **The desktop companion no longer drags you out of full screen.** With Skales in macOS full screen and the companion switched on, opening Studio or Skales Code was close to unusable: the content opened where it should, but the companion surfaced on another desktop and the system followed it there, again and again, every time it resized itself to fit what it was saying. It was told it could appear on every desktop except a full-screen one, which left it nowhere to be while you were in full screen - so macOS left full screen instead. It now floats over your full-screen space where you can see it, and stays out of the way: it comes up without taking the keyboard, and takes it only for as long as you have its input open. The app's icon stays in the Dock, as before.

- **Switching Skales to full screen no longer summons the companion.** Going into a full-screen space, and coming back out, took the window off screen for the length of the animation, and Skales read that as you putting it away - so a companion appeared over a window you were looking at the whole time. Which half of the animation got there first decided whether one showed up, which is why it happened on some switches and not others. Skales now asks the window whether it actually went anywhere. Minimising still brings the companion, exactly as before.

- **A first run that cannot save now says so.** The last press of the setup writes your answers, your licence acceptance and your settings, and if any of that failed the press simply stopped working: no message, no explanation, the same button waiting to be pressed again. It now names what went wrong, in the same place and the same words as every other step of the setup, and nothing is thrown away - your answers stay on screen and the press can be repeated once the cause is gone.

- **The Guide stopped calling a path ready when nothing can answer it.** Cards that hand you a ready-made instruction - make a picture, read this document, plan my week, watch this video - read as ready on a machine with no language model configured, and the instruction then landed in a composer that had nothing to send it to. Every card that offers an instruction now asks for a model first and says so, and there is no longer a way to add a new one that forgets to.

- **The introduction no longer invents applause for you.** The card that shows what the Visuals studio makes was drawn as a post of your own with twenty-four likes under it - a number about something that does not exist, shown to somebody who has not made anything yet. The number is gone.

- **When your chat model cannot see a picture, the model that reads it is the one you named.** Where the model running the turn is text-only, Skales hands the picture to another model on the same provider - and it was picking that reader by the model's NAME, from a rule about which generations of a family can see. So an install that had a vision model set under the Vision Provider, and had answered the "can this model see images?" question in Settings, still watched a different model read the picture because that other one happened to match the naming rule first. The order is now the one the settings card promises: the answer you gave for a model comes first, the vision model configured for that provider comes second, and what the daemon reports and the name rules guess are consulted only where neither exists. A model you marked "cannot see" is never handed a picture again, however it is named, and a vision model you configured is used even when the daemon has not got it - an error naming the model you chose is worth more than a silent substitution.
- **The vision model you configured is used on every provider, not only on a local one.** On OpenRouter an image turn from a text-only model always went to one fixed cheap model, and on the remaining providers it was refused outright - in both cases the vision model set in Settings was carried along and never asked. Now every provider follows the same order: the answer you gave for a model, then the vision model configured for that same provider, and only then the old behaviour, which is unchanged where you configured nothing. A model configured for one provider is still never sent to another.

- **A control a plugin page hides now actually disappears.** Every plugin page in Skales stands on the same small stylesheet, and that stylesheet's rule for buttons beat the browser's own rule for hidden things - so a button a page had hidden stayed on screen. It showed up as a Stop button sitting beside a recorder that was not recording, and it would have shown up in every page that hides anything.

- **Switching a plugin off, or deleting one, now says so when it does not work.** Both asked the machine and threw the answer away: the shelf redrew, the plugin was still there, and nothing on screen explained it. A failure is now a sentence on the plugin it happened to, with a Try again beside it, and deleting reports what is actually true - a folder that is still on the disk afterwards is not a deletion.

- **A plugin page is told what kind of thing went wrong, not just that something did.** Every failure reached a plugin's page as one word, so a page could not tell a busy mail server from a tool it will never be allowed to use, and pages retried refusals for ever. A tool call now answers with what happened, what it was called, and whether trying again could come out differently.

- **A tool approval raised at the desk now reaches your phone, and can be answered there.** A run that stops to ask before it deletes, sends or deploys put its card in front of whoever was at the computer. On a paired phone the same session merely said it was waiting: the question, and the button that answers it, only ever travelled for a run the phone had started itself - and for a turn that had been queued behind another one, not even then. The waiting question is now published where it is raised, so it reaches every paired phone whatever started the run, with the same card and the same two buttons as before. Answering it at the computer takes the card off the phone again, and a run that is stopped or that ends while waiting takes it with it, so nothing is left standing that resolves nothing. A phone that was switched off while the run was waiting is not sent a question hours late - it is told what the session is waiting on the moment it opens it, and in the session list, so it can answer it then.

### Changed

- **The coding window stops asking whether it may send a sub-agent.** A session set to Auto may already write files and run commands in its folder without a card, and then stopped to ask whether it could hand a reading errand to a helper - the cheapest and least risky thing it does. In Auto it now delegates without asking. Every other mode is untouched: a session in Code still asks, a session in Plan still refuses, and the WhatsApp channel is unchanged.

- **The setup no longer decides that you want the tour.** The last screen of the first run used to hand everybody the introduction story on the way into the app, whether they wanted it or not. It now asks: Start with Skales is the press that opens the app, watching the short introduction is the one next to it, and a line underneath says it stays in the Guide for whenever you feel like it. Both presses save exactly the same thing - only where you land differs - so choosing the story is never the price of finishing the setup, and a reader who takes it still gets their suggested first prompt waiting in the composer afterwards. Walking the setup a second time is not offered the story at all, because it was never shown it.

- **The screen that shows off Skales stopped introducing things twice.** The block of feature cards in the setup is where you switch AIPointer, Buddy, Iris and the Visuals studio on or off, and it carried one more card that had nothing to switch: tasks and goals, which are simply always there. The introduction story explains what they do a screen later, with the same picture. Explaining belongs there; this block decides, and it is shorter for it.

- **A plugin's own files no longer travel with its code to your phone.** The plugin your phone fetches from this machine is capped, and the cap is the right size for a page and a manifest. A board of photographs is not, so a plugin that worked perfectly well became "too large" on the day somebody used it enough. The code now travels on its own and what your use of the plugin piled up beside it is counted under its own name instead.


- **A plugin's own files now survive every update, and the card names them before you press it.** A plugin folder holds two kinds of file that look alike: the plugin itself - its page, its tools, its text - and everything that came out of USING it. Only one file was ever protected by name, so a plugin that kept a year of receipts in a file of its own could have them written over by an update it never asked for. Skales now draws that line in one place: the plugin's store and everything in its data folder belong to you, are never written over by an update, and never travel in a package you export. The confirmation card lists them by name before the update runs, next to what the update does replace, so what you are keeping is as readable as what you are changing.

- **The plugin shelf says whether a plugin can actually be used.** A row had a switch, and a switch only says whether somebody turned the plugin on. A plugin could be on and do nothing at all - an automation on a machine with no provider set up, a plugin whose page was never written - and the only way to find out was to open it and watch nothing happen. Each row now carries a word for what it can do: ready, needs setting up, running, waiting for its next run, switched off, or not working; where something is missing, the row says what and links to the screen that fixes it. The row also says where the plugin runs and where its files are, and Opening it is now a button with a word on it rather than one of four identical grey squares - exporting and deleting are the quieter pair beside it.

- **Naming a new plugin after one that is already here is refused instead of quietly replacing it.** Typing a title in the New field made an id out of it, and two different titles can make the same id. The plugin that was already there was replaced with a blank page and the screen said "created". It now refuses, names the plugin whose name it is, and writes nothing. Every other way a plugin arrives - built in chat, installed, imported - still updates the one you meant.
